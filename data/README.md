# Demo Corpus & Gold-Standard Evaluation Set

This folder holds the files RAGNova will index, plus the test questions we use to *measure* whether retrieval works.

**Fill this file in on Day 1, before writing any code.** Writing the test set before the system is deliberate: it stops us from unconsciously tuning the system to flatter itself. See Chapter 1 §3.3 and §1.10.

---

## Folder layout

```
data/
├── documents/   PDFs and DOCX files
├── images/      PNG / JPG — include screenshots and photos containing text
└── audio/       WAV / MP3 clips, 30 s to 3 min
```

Target: 10–15 PDFs, 5–8 DOCX, 10–15 images (3+ screenshots, 3+ photos with visible text), 3–5 audio clips.

## Deliberate cross-modal test material

Make sure the corpus contains, on purpose:

- [x] An image **and** a document about the same topic → proves image→document retrieval (`images/screenshot_wifi_setup.png` and `documents/it_onboarding.docx`).
- [x] An audio clip mentioning a topic that also appears in a PDF → proves audio→document retrieval (`audio/hod_project_announcement.wav` and `documents/notice.pdf`).
- [x] A screenshot whose content is described in a document → proves text→image retrieval with a visible payoff (`images/screenshot_synopsis_portal.png` and `documents/notice.pdf`).

## Gold-standard question set

The evaluation set from Chapter 1 §1.10. Start with 5 questions on Day 1; grow to **20 text questions + 10 cross-modal queries** by Chapter 7, when we first measure Recall@5 and MRR.

**Current state (Ch12, 2026-10-05): 25 text questions, 16 cross-modal (8 text→image, 4 image→document, 4 audio topic), 4 negative controls.** Both targets (20 text, 10 cross-modal) are met now that the corpus grew past the three synthetic files: T1–T13 were written against the starter set, T14–T25 and I5–I8, M3–M4, A3–A4 against the downloaded study materials. Every new row was written *before* it was measured, so none was tuned to flatter the system.

**The questions live in [`gold_set.json`](gold_set.json)**, which `scripts/evaluate_*.py` and `tests/test_retrieval.py` read through `src/core/gold.py`. The tables below are the human-readable view; `tests/test_gold_set.py` fails if they drift from the JSON (four hand-copied lists drifted before this). `python scripts/check_gold_set.py` verifies every expected file and page exists and prints each question's wording overlap.

> **Wording overlap, measured, not promised** (`python scripts/check_gold_set.py`, 2026-10-05). For each text question: the share of its content words (4+ letters, common words removed) that also appear in the best matching chunk on the answer page. Across the 25 questions the median is 50% and the range 27–88%; **none is zero**, because a question has to name its topic. The nine above 50% are T3, T7, T12, T18, T19, T20, T22, T23, T24. The lowest are T21 (27%), T15 (31%) and T1, T14, T16 (33%), which are the better demonstrations of meaning over keywords. The "shares no words with…" notes in the Why column compare only against the quoted answer phrase and were checked by hand. This replaces the earlier blanket claim of "no shared keywords". Whether dense retrieval really beats keyword search (Ctrl+F, BM25) on these questions would need a BM25 baseline run; that has **not** been done.
